# Рио Радар — дизайн

Дата: 2026-10-03. Статус: согласован в обсуждении, ждёт проверки документа.

## Цель

Одностраничный сайт, который показывает лучшие цены на авиабилеты
Москва → Рио-де-Жанейро на период декабрь 2026 — февраль 2027,
для 1 или 2 взрослых, только у проверенных перевозчиков,
не более 2 пересадок, в режимах «туда» и «туда и обратно».
Главный критерий качества помимо корректности: сайтом приятно пользоваться.

Образец по структуре и настроению: rioradar-cowk75mg.manus.space.

## Решения, принятые в обсуждении

| Режимы | «Туда» и «Туда и обратно», переключатель |
| Возврат в режиме «туда и обратно» | Два способа: точная дата возврата или диапазон длительности поездки |

## Источник данных (уточнено после проверки с живым токеном)

REST-методы Data API отдают один самый дешёвый билет на дату, и для Москва → Рио
он почти всегда у стыковочных комбинаций с 3–4 пересадками вне белого списка:
под фильтр проходил 1 день из 90. Поэтому используется GraphQL-версия того же API:
`POST https://api.travelpayouts.com/graphql/v1/query`, заголовок `X-Access-Token`.

- `prices_one_way(params: {origin, destination, depart_months: ["YYYY-MM-01"], depart_dates: []}, grouping: NONE, paging: {limit: 400, offset}, sorting: VALUE_ASC)`
  отдаёт все билеты месяца из кеша (500–600 на месяц), по 10–20 на дату.
  Листаем страницами по 400 до короткой страницы, максимум 6 страниц.
- `prices_round_trip(params: {depart_dates: [d], return_dates: [r]})` для точной пары дат,
  `prices_round_trip(params: {depart_dates: [d], return_dates: [], trip_duration_min, trip_duration_max})` для окна длительности.
- Поля билета: `departure_at`, `return_at`, `value` (рубли, с копейками), `number_of_changes`,
  `main_airline`, `duration` (минуты, всего), `convenient` (флаг «удобный» от Aviasales),
  `found_at` (unix-секунды), `origin_airport_iata`, `destination_airport_iata`, `ticket_link`
  (добавить к `https://www.aviasales.ru/search`), `segments[].flight_legs[]` с
  `operating_carrier` каждого плеча.
- Лимит: 60 запросов в минуту. Календарь = 3 месяца × 2 страницы = 6 запросов, кеш 30 минут.
- Данные — кеш поисков пользователей Aviasales за последние 48 часов, хранятся до 7 дней.
- Цена только за одного взрослого; на двоих удваиваем с пометкой «расчётно».

Правило фильтра (решение владельца):

- основной перевозчик (`main_airline`) из белого списка: EK, QR, TK, EY, ET, SU;
- каждое плечо либо у перевозчика из белого списка, либо у партнёров для внутреннего
  перелёта по Бразилии: LATAM (LA, JJ) и GOL (G3). Плечо на Победе, Pegasus, AJet,
  flydubai и прочих отсекает билет с причиной «плечо на X»;
- не больше 2 пересадок в каждую сторону (пересадки считаем по плечам сегмента).

На живых данных 2026-10-03: 1613 билетов за три месяца, 264 подходят, 88 из 90 дней с вариантами.

Hono выбран потому, что одно и то же приложение запускается на Node,
Cloudflare Workers и Vercel без изменения кода маршрутов.

## Экран и взаимодействие

Одна страница. Палитра: глубокий зелёный фон, жёлтый акцент для цен
и кнопок, синий для выделенного дня, светлый текст. В шапке силуэт
статуи Христа-Искупителя в SVG и маршрут «🇷🇺 Москва → 🇧🇷 Рио-де-Жанейро».

Панель управления (прилипает к верху при прокрутке):

- переключатель «Туда / Туда и обратно»;
- переключатель «1 взрослый / 2 взрослых»;
- фильтр пересадок «до 1 / до 2»;
- в режиме «туда и обратно»: выбор «Точная дата возврата» или
  «Длительность», для длительности два ползунка 3–30 дней (по умолчанию 7–21).

Календарь: три месяца подряд одним полотном, без переключения между
месяцами. В каждой клетке: число, цена в рублях, метка числа пересадок.
Три самых дешёвых дня в каждом месяце подсвечены. Дни без данных:
серые с прочерком. Дни, где лучший билет не из белого списка или
с лишними пересадками: серые с подписью причины («только Air Arabia»,
«3 пересадки»). Прошедшие дни недоступны. Клик по дню выделяет его.
При смене пассажиров или фильтра пересадок цены в календаре
пересчитываются на клиенте мгновенно, без запроса к серверу.

Карточка выбранного дня (справа на широком экране, снизу на телефоне):
логотип и название авиакомпании, полное время в пути, число пересадок,
аэропорты вылета и прилёта, цена за выбранное число пассажиров
с пометкой «расчётная» для двоих, кнопка «Открыть на Aviasales».

Режим «туда и обратно»:

- Точная дата возврата: после выбора дня вылета второй клик по календарю
  выбирает день возврата (подсвечивается диапазон). Карточка показывает
  до 5 вариантов на эту пару дат, отсортированных по цене.
- Длительность: клик по дню вылета показывает список лучших пар дат
  в заданном окне длительности, отсортированных по цене, до 10 штук.

Состояние (режим, пассажиры, пересадки, выбранные даты, длительность)
синхронизируется с адресной строкой: ссылку можно сохранить.

Внизу строка статуса: источник, время последней проверки (МСК),
число дней с подходящими данными из общего числа дней периода.

Адаптив: на ширине до 720 px месяцы идут друг под другом в одну колонку,
клетки уменьшаются, но остаются сеткой 7 дней в ряд, карточка переходит
под календарь. Горизонтальной прокрутки нет.

## Поток данных

Страница ходит только в свой сервер.

`GET /api/calendar`
Сервер запрашивает все билеты каждого месяца через `prices_one_way`, нормализует
и группирует по дате: `days[date] = { best, options (до 10 подходящих по цене),
cheapestAny (самый дешёвый вообще, даже вне фильтра), total, allowedCount }`.
Каждое предложение нормализуется:

```
{ date, price, airline, airlineName, transfers, durationMin,
  originAirport, destinationAirport, departureAt, link,
  allowed: true | false, reason: null | "airline" | "transfers" }
```

Фильтр по белому списку и пересадкам выполняется на сервере, но
отфильтрованные дни не удаляются, а помечаются `allowed=false` с причиной.
Клиентский фильтр «до 1 пересадки» применяется поверх уже на странице.

`GET /api/roundtrip?depart=YYYY-MM-DD&return=YYYY-MM-DD`
Один запрос `prices_for_dates` с `one_way=false`, результат фильтруется
по белому списку и пересадкам в обе стороны, сортируется по цене, до 5 штук.

`GET /api/roundtrip?depart=YYYY-MM-DD&minDays=7&maxDays=21`
Запрос `grouped_prices` с `departure_at=YYYY-MM-DD`, `return_at=YYYY-MM`
для месяцев, попадающих в окно, с `min_trip_duration` / `max_trip_duration`.
Результат фильтруется, сортируется по цене, до 10 штук.

`GET /api/status`
Время последнего успешного ответа Travelpayouts, число дней с данными,
число дней с подходящими предложениями.

Кеш: каждый ответ Travelpayouts хранится в памяти 30 минут по ключу
запроса. На Cloudflare Workers память не переживает перезапуск изолята,
это приемлемо: лимиты API в 20 раз выше нашего потребления.

Цена на двоих: `price * 2`, поле `estimated: true`.
Ссылка на Aviasales: `https://www.aviasales.ru/search/MOW0112RIO1`
для «туда» и `MOW0112RIO1502` плюс число взрослых для «туда и обратно».
Формат: `{origin}{DDMM}{destination}[{DDMM}]{adults}`.

Настройки в `config.js`: период (список месяцев), белый список с кодами
и названиями, максимум пересадок, TTL кеша, коды городов.
Токен в `.env`, переменная `TP_TOKEN`.

## Ошибки и пустые данные

- Нет токена: сервер при старте пишет понятное сообщение и не запускается.
- Travelpayouts недоступен или ответил ошибкой: сервер отдаёт последний
  успешный кеш, если он есть, с пометкой `stale: true`; страница показывает
  жёлтую плашку «Данные от HH:MM, источник временно недоступен».
  Если кеша нет, страница показывает календарь без цен и плашку с кнопкой
  «Повторить».
- Ответ 429: считается ошибкой источника, см. выше.
- На дату нет данных: клетка с прочерком, подсказка при наведении
  «Aviasales не нашёл билетов на эту дату за последние 48 часов».
- Все дни пустые: отдельное сообщение с объяснением про кеш
  и предложением вернуться позже.
- Некорректные параметры запроса к `/api/*`: ответ 400 с текстом.

## Тестирование

`node --test`, без дополнительных библиотек.

- `offers.test.js`: нормализация ответа API, фильтр по белому списку
  с причиной, фильтр по пересадкам в одну и обе стороны, удвоение цены
  с флагом, сборка ссылки на Aviasales для обоих режимов,
  выбор трёх самых дешёвых дней месяца.
- `app.test.js`: маршруты `/api/*` с подменённым клиентом Travelpayouts:
  склейка месяцев, кеш (второй вызов не идёт в API), поведение при ошибке
  источника с кешем и без, валидация параметров.
- Ручная проверка в браузере: открыть страницу, переключить режимы,
  выбрать даты, проверить ссылку на Aviasales, посмотреть на ширине телефона.
